Cursor, Codex, Grok, Pi를 함께 사용하면서 같은 스킬이 여러 폴더에 복사되기 시작했다. 한 곳을 고치면 다른 곳은 오래된 내용을 읽고, 설치 스크립트가 다시 복사하면 수정이 되돌아갔다.

> “그록, 파이, 커서는 `.agents/skills`를 기본 스캔한다고 하더라구. … 그래서 클로드 전용을 제외하고는 전부 통합하려고 하는데 내가 아는 게 맞는지 확인 좀해줘”

> “gstack, gbrain은 공유 외부 스킬이고 / bb cli는 local only가 맞아”

이 문제를 정리하면서 스킬도 npm 패키지나 라이브러리와 비슷한 의존성이라는 관점이 생겼다. 중요한 것은 파일을 어디에 두는가가 아니라, 원본·배포 범위·실행 권한을 분리하는 것이다.

## 세 가지를 분리해야 한다

### 1. 원본

스킬의 실제 소스는 한 곳에 있어야 한다. 여러 에이전트 디렉터리에 파일을 복사하면 어느 파일이 최신인지 알 수 없어진다. git 저장소나 중앙 registry를 source of truth로 두고, 각 에이전트는 그 원본을 발견할 수 있게 연결한다.

### 2. 배포 범위

모든 기기에 같은 스킬이 필요한 것은 아니다.

| 종류 | 의미 |
| --- | --- |
| 공유 외부 스킬 | 여러 기기에서 내려받아도 되는 재사용 리소스 |
| 프로젝트 스킬 | 특정 저장소의 코드와 함께 있어야 하는 규칙 |
| 로컬 전용 스킬 | 한 기기의 경로·서비스·권한에 묶인 도구 |

예를 들어 일반적인 코드 리뷰 스킬은 공유할 수 있지만, 특정 컴퓨터의 BB 운영 명령이나 개인 경로를 전제로 하는 스킬은 로컬 전용으로 남겨야 한다.

### 3. 실행 권한

공유할 수 있다는 사실과 실행을 허용한다는 사실은 다르다. 스킬을 다른 기기에 내려받았더라도, 그 스킬이 어떤 명령을 실행할 수 있는지는 별도의 allowlist로 제한할 수 있어야 한다.

```yaml
skills:
  shared:
    - explain-diff
    - gstack
  localOnly:
    - bb-cli

permissions:
  allow:
    - read_project_files
    - run_tests
  deny:
    - delete_outside_workspace
```

이 예시에서 `shared`는 배포 정책이고 `permissions`는 실행 정책이다. 둘을 하나의 설치 목록으로 합치면, 스킬을 설치할 수 있다는 이유만으로 위험한 작업까지 허용하기 쉽다.

## 심링크는 편리하지만 원본을 대신하지 않는다

심링크는 여러 에이전트가 같은 파일을 보게 해 주지만, 그 파일이 어디에서 관리되는지는 별도로 문서화해야 한다. 심링크를 복사본처럼 취급하거나 설치 스크립트가 매번 덮어쓰면 결국 드리프트가 생긴다.

좋은 구조는 다음과 같다.

```text
registry-pool/skills/explain-diff  ← 원본
                 ├─ .agents/skills/explain-diff  ← 발견 경로
                 ├─ .codex/skills/explain-diff   ← 필요할 때만 연결
                 └─ .claude/skills/explain-diff  ← provider 전용일 때만 연결
```

다만 모든 에이전트가 실제로 같은 탐색 경로를 읽는지 확인하지 않고 “심링크를 만들었으니 되겠지”라고 가정하면 안 된다. provider마다 읽는 위치와 지침 로딩 방식이 다를 수 있기 때문이다.

## 기기 분기는 새 문법보다 표시 규칙으로

기기마다 다른 경로가 필요하다고 해서 스킬마다 새로운 조건 문법을 만들면 학습해야 할 언어가 하나 더 생긴다. 공통 문서에는 기기와 무관한 규칙을 두고, 필요한 부분만 명시적인 표시로 나누는 편이 단순하다.

```html
<!-- device: mini -->
이 블록은 mini에서만 적용한다.
```

이렇게 하면 agent가 문서를 읽을 때 조건을 발견할 수 있고, 실제 경로와 서비스 정보는 기기별 문서에 격리할 수 있다.

## 정리

- 스킬의 원본과 발견 경로를 분리한다.
- 공유 가능 여부와 실행 권한을 분리한다.
- 심링크는 배포 방식이지 source of truth가 아니다.
- 로컬 경로와 서비스에 묶인 스킬은 공유하지 않는다.
- 기기 분기는 새로운 DSL보다 명시적인 문서 규칙으로 관리한다.
